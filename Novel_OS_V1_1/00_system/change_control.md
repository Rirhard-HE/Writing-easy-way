# Author Setting Change Control

## 核心规则

作者可以随时增加或修改设定。Agent 的职责是识别影响、提示明显冲突、维护引用与历史，而不是用旧设定否决作者。

## 变更分类

| 类型 | 含义 | 默认处理 |
|---|---|---|
| `ADD` | 新增、且未与权威事实冲突 | 记录来源与影响，按作者明确指令应用 |
| `CLARIFY` | 收窄或解释已有设定，不改变核心含义 | 更新权威表述，保留原措辞来源 |
| `OVERRIDE` | 当前作者决定直接取代旧事实 | 先提示冲突和影响，再按明确决定替换 |
| `RETCON` | 改写已进入故事历史的事实 | 生成影响清单；作者明确批准后应用并标记旧版本 |
| `DEPRECATE` | 停止继续使用某设定，但保留历史 | 标记 `DEPRECATED` 或 `SUPERSEDED`，不得删除证据 |

## 是否属于正式决定

- “我在考虑”“也许”“如果……会怎样”默认是讨论或提案。
- “设定为”“确认”“修改为”“以后按照”“Retcon 为”“覆盖原设定”是明确决定。
- 语义不清且会改变 Canon、谜底、死亡/复活或身份时，必须询问作者。

## 影响扫描顺序

1. 当前章节作者输入与作者决定；
2. `01_canon/secret/` 与普通 Canon；
3. `02_characters/`、`03_world/` 当前状态；
4. `06_memory/` 已批准事件与状态 Delta；
5. `05_manuscript/` 已批准正文；
6. `04_story/` 计划、伏笔与开放线程；
7. `00_sources/` 和 Genesis 审计中的旧原稿证据。

## 冲突提醒格式

```text
SETTING_CONFLICT <severity> <change_type>
新作者设定：...
旧权威事实：...
证据：path / ID / chapter
影响：受影响的人物、事件、章节、伏笔或规则
处理：按作者明确覆盖执行 / 等待作者确认 / 仅记录为提案
```

严重度：

- `BLOCKER`：变更意图不清，且涉及谜底、死亡/复活、身份或互斥世界硬规则；
- `HIGH`：会改变已批准章节、多个实体状态或关键因果链；
- `MEDIUM`：局部连续性需要同步；
- `LOW`：措辞、别名或无剧情影响的细节；
- `LEGACY_ONLY`：只与未被批准为 Canon 的旧原稿冲突。

## 应用规则

1. 明确的作者 `OVERRIDE/RETCON` 在提示影响后可以应用，不要求旧设定“同意”。
2. 模糊意图不能自动写回 Canon。
3. 被替代事实必须保留 `superseded_by`、原来源、决定来源与日期。
4. 受影响的角色状态、世界卡、事件、伏笔、章节卡和索引必须同步更新或列入待办。
5. 对已批准正文的修改必须单独列出，不得通过修改 Canon 隐式改写正文。
6. 每次应用后运行索引重建、工程校验和受影响连续性检查。

## 章节内变更

作者在 `00_author_brief.md` 的“本章新增或修改设定”中声明变更。Agent 在冲突报告中给出影响，作者在 `04_author_decision.md` 确认处理方式，最终通过 `07_memory_delta.agent.yaml` 与 `08_approval.yaml` 写回。

## 章节外变更

章节外的明确作者设定先形成一个带来源和影响分析的变更记录。若作者原话已经明确要求覆盖，可在同一任务提示冲突后应用；否则保持提案状态等待确认。
