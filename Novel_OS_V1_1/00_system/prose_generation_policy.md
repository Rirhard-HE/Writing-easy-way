# Prose Fidelity and Authorial-Voice Policy

## 目标

在不改变作者材料的核心观点、事实关系、逻辑结构、事件顺序、知识边界和有效信息量的前提下，把生产正文调整为更接近真实作者持续写作的版本：保留原意，降低模板感，改变句法分布，减少过度概括，增加有因果与人物功能的真实写作痕迹，并保持小说既有风格一致。

“降低 AI 感”不是独立于内容的装饰性润色，也不是把文字故意写差。任何自然化改写都必须服从剧情、Canon、人物知识、揭示门和作者当章风格要求。

从 `CH_0009` 起，生成与终审同时执行 `00_system/prose_style_profile.md`（`daily_light_detailed_v1`）：保留日常轻松的基准语感，增强有功能的环境细节与有层次的对话细节。严肃场景不得为了轻松感削弱情绪后果。

每次生成还自动执行 `00_system/narrative_generation_directive.md`（`situated_prose_v1`）。作者没有逐次审阅或重复风格要求时仍按该指令保持一致；这不构成正文、Delta、Canon 或受控写回批准。

## 不可损失层

自然化改写前后必须保持：

1. 核心观点与场景目的；
2. 已发生事件、因果方向和先后顺序；
3. 人物关系、动机、态度和决策强度；
4. 世界事实、机构口径、角色认知与不确定性层级；
5. 必须发生、禁止发生和伏笔/揭示边界；
6. 对后续剧情有用的有效信息量。

不得为了“像人写的”而删掉困难信息、模糊精确边界、改变谁知道什么、用更顺口的说法偷换结论，或把人物推测升级为客观事实。

## 生成顺序

1. 先抽取作者固定内容、事实—因果链、信息点和情绪落点。
2. 检查作者输入与现行状态的逻辑、时间线、角色知识和信息缺口。
3. 明显缺口或矛盾会影响主线、人物选择、场景因果、揭示或长期状态时，标记 `BLOCKER/HIGH` 并向作者索取信息；不得用 Agent 新设定填洞。
4. 不影响核心的局部歧义可提出有边界的解释，但必须在提案中标为 Agent 假设，不能伪装成作者事实。
5. 在已批准边界内先完整生成场景，不以长度目标预先截断信息。
6. 生成后执行长度、重复、负面清单、语义保持、模板感、风格一致性和梗/语域检查。

## 可执行的自然化原则

### 句法和段落分布

- 避免连续使用长度、结构和重音相同的句子；短句、复句、插入语和省略应由人物状态与场景动作决定。
- 避免把每个动作拆成等宽的一句一段，也避免把所有信息压入工整长段。
- 对话、动作、观察和环境反应应自然交错，不按固定循环机械排列。
- 允许局部不对称：人物临时改口、没说完的话、答非所问、现实事务打断情绪，但每一处都要符合人物和情境。

### 降低模板感

- 检索并控制“随后、然后、这一刻、忽然意识到、空气安静、沉默几秒、像是在确认、某种复杂情绪”等高频支架。
- 不连续使用“不是……而是……”“仿佛……又像……”“直到此刻他才明白”等总结型模板。
- 同一章和最近章节中的显眼比喻、动作、物件和收束方式不得无功能复用。
- 不为了显得深刻，在已经由动作和对话表达完成后再补一段抽象总结。

### 降低过度概括

- 能通过谁做了什么、看见什么、说了什么表现的信息，不改写成泛化结论。
- 制度压迫、关系亲密、职业受限和心理变化优先由具体案例及反应建立。
- 必须概括跨期事实时，保留范围、来源和不确定性，不写成全世界通则。

### 真实写作痕迹

- 使用角色会注意的选择性细节，而不是平均给所有物件分配描写。
- 保留生活中的误差、旧物、顺手动作、抢话、局部尴尬和不完全回应，使其承担人物、因果或节奏功能。
- 不以随机错别字、病句、无意义口头禅、强行粗俗或故意降质模拟“人类写作”。
- 幽默应来自人物关系、处境反差和既有经验，不靠旁白替读者解释笑点。

### 性格不是单一开关

- 角色的显著特质是概率倾向和反应范围，不是需要逐句兑现的标签。幽默的人不必持续开玩笑，冷酷的人也会权衡、疲惫、迟疑或对特定关系表现柔软。
- 生成动作与对话前，至少核对当前目标、压力、身体状态、关系、场合、风险和前序刺激；细节必须体现这些变量对表达的影响。
- 不用反复复制同一种讽刺、冷脸、沉默、粗口或机智回答来维持辨识度。人物辨识度应来自选择方式、价值排序、回避习惯和关系差异。
- 允许人物出现有依据的反差，但不得随机切换性格，也不得通过旁白宣布“他其实很多面”代替场景证据。

## 网络梗与中文圈语感

- 网络梗只在人物性格、情绪、关系亲密度、场景压力和知识来源都允许时进入人物表达。
- 梗不得替代关键事实、人物决定或必要解释；删掉梗后，场景逻辑仍须成立。
- 不在严肃情绪尚未落地时用梗强行卸压，不让所有人物共享同一种网络口吻。
- 同一场景不得堆叠多个梗或让梗成为作者炫技；出现频率以不压过人物本身为上限。
- 当代现实中文互联网原句、平台名、真人/事件指涉若会造成时代错置、文化来源泄漏或角色知识越界，不得直接使用。可改造成符合世界内历史、地方习惯和人物口吻的“梗式表达”，但不得借此暗示未批准的文化传承。
- 旁白原则上不直接追逐流行梗；除非作者已建立稳定的叙述者语域。

## 作者输入逻辑检查

作者输入拥有创作权威，但不被假定为天然无矛盾。Agent 必须检查：

- 事件是否具备前因、触发条件和可执行结果；
- 人物是否有理由、有能力并且有知识采取该行动；
- 时间、地点、距离、伤势、物品和组织权限是否支持场景；
- 新信息是否与 Canon、最近正文、秘密揭示门或同章其他要求冲突；
- “必须发生”与“禁止发生”是否互斥；
- 代词、称呼、时间词、程度词和省略信息是否导致多个实质不同解释；
- 作者要求的情绪落点是否有足够场景证据，而非只能靠旁白宣布。

处理规则：

- 可由权威文件唯一确定的缺口：按权威状态补齐并注明证据。
- 只影响可逆局部表达的轻微歧义：在提案中列出受限假设，作者可修改。
- 会改变剧情、人物选择、世界规则、揭示、因果或长期状态的明显缺口：暂停正文生成，明确说明缺什么、为什么影响结果，并向作者索取信息。
- 不得因作者输入可能有问题而泛泛质疑；问题必须具体到冲突事实、缺失变量及其影响。

## 审阅门

从 `CH_0009` 起，`06_final_review.agent.md` 必须分别记录并通过：

- `meaning_preservation_review`：核心观点、事实关系、逻辑结构和有效信息量未被自然化改写损失；
- `ai_pattern_review`：无明显连续模板句、机械段落节拍、过度概括或重复收束；
- `style_consistency_review`：与作者当章材料、最近获批章节和角色口吻一致；
- `character_range_review`：人物显著特质未被写成全天候标签；反应变化具有目标、压力、关系和现场依据，且无随机变脸；
- `narrative_method_review`：三层信息边界、环境侧面描写与连续性、物件复用、反电影分镜化和对话段落节奏均符合 `situated_prose_v1`；
- `meme_register_review`：梗、俚语和幽默符合人物、场景、时代与揭示边界；未使用时也记录为 `PASS`；
- `logic_gap_review`：作者输入与成稿中的明显逻辑缺口均已解决或取得作者决定。

任一项不是 `PASS`，正文不得进入最终批准或 Delta。
